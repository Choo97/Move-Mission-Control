# 관리자 기능 가이드

이 문서는 React 관리자 화면의 메뉴 구성과 예약 운영 기준을 설명합니다. 세부 API 형식은 [API 문서](API.md), 화면 스타일은 [디자인 가이드](DESIGN.md)에서 확인합니다.

## 화면 경로

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 로그인 | `/admin/login` | 관리자 인증 |
| 예약 관리 | `/admin/reservations` | 처리 우선순위, 검색, 필터, 예약 상세 이동 |
| 예약 상세 | `/admin/reservations/{id}` | 견적, 상태, 고객 요청, 알림, 운영 이력 처리 |
| 알림 이력 | `/admin/notifications` | 이메일·SMS 발송 상태와 실패 원인 확인 |
| 리뷰 관리 | `/admin/reviews` | 공개 여부와 관리자 답변 관리 |
| 운영 설정 | `/admin/availability` | 서비스 모드, 운영시간, 휴무일, 견적 정책 설정 |
| FAQ 관리 | `/admin/faqs` | 고객 FAQ 등록, 수정, 공개 상태 관리 |
| 운영 가이드 | `/admin/guide` | 오늘 처리할 항목과 업무 순서 확인 |

## 접근 권한

현재 개인 프로젝트 단계에서는 `ADMIN` 권한 하나를 사용합니다.

- 고객 화면과 고객 API는 로그인 없이 접근할 수 있습니다.
- `/admin/**`와 `/api/admin/**`는 로그인한 관리자만 접근할 수 있습니다.
- 인증되지 않은 관리자 API 요청은 `401`, 권한이 부족한 요청은 `403`을 반환합니다.
- 로그인 세션이 만료되면 관리자 화면에서 재로그인을 안내합니다.

역할을 미리 세분화하지 않은 이유는 혼자 운영하는 단계에서 불필요한 권한 규칙을 늘리지 않기 위해서입니다. 여러 운영자가 생기면 예약·콘텐츠·시스템 관리 권한을 분리할 수 있습니다.

## 예약 운영 흐름

```text
접수 확인 -> 고객 정보 확인 -> 거리·현장 조건 점검 -> 견적 안내
-> 고객 동의 확인 -> 일정 확정 -> 이사 완료
```

예약 목록에서는 전체 운영의 우선순위를 판단하고, 예약 상세에서는 한 건의 처리를 완료합니다.

- `접수 대기`: 상담을 시작해야 하는 예약
- `고객 요청 대기`: 수정·취소 요청의 승인 또는 반려가 필요한 예약
- `거리 확인 필요`: 거리와 현장 조건을 확인해야 하는 예약
- `고객 동의 대기`: 견적 안내 후 고객 응답을 기다리는 예약
- `알림 실패`: 이메일 또는 SMS 재확인이 필요한 예약

## 예약 상세 구성

상세 화면은 관리자가 판단한 뒤 처리하고, 마지막으로 이력을 확인하는 순서로 배치합니다.

1. `고객 흐름 요약`: 현재 상태와 다음 처리 항목
2. `기본 예약 정보`: 고객, 연락처, 일정, 주소, 거리, 견적
3. `현장 정보와 짐 사진`: 층수, 엘리베이터, 사다리차, 첨부 사진
4. `운영 처리`: 상태, 거리, 견적, 관리자 메모 저장
5. `고객 요청 처리`: 수정·취소 요청 승인 또는 반려
6. `운영·알림 이력`: 변경 주체, 변경 시각, 발송 결과 확인

주소, 파일명, 안내 문구가 길어져도 버튼이나 값이 겹치지 않도록 정보 영역과 작업 영역을 분리합니다.

## 운영 규칙

### 고객 수정·취소 요청

고객 요청은 예약 데이터에 즉시 반영하지 않습니다. 관리자가 내용을 확인한 뒤 승인하면 실제 예약을 변경하고, 반려하면 원래 예약을 유지합니다. 일정과 주소 변경이 배차와 견적에 직접 영향을 줄 수 있기 때문입니다.

### 알림 이력

알림 처리 대상은 실패·대기 건을 빠르게 찾는 용도이고, 전체 알림 이력은 수신자와 발송 결과를 추적하는 용도입니다. 두 화면 모두 예약 상세로 연결됩니다.

### 리뷰와 FAQ

리뷰 원문은 수정하지 않고 공개 상태와 관리자 답변만 관리합니다. FAQ는 질문, 답변, 정렬 순서, 공개 상태를 관리하며 고객 화면에서 결과를 확인할 수 있습니다.

### 서비스 운영 모드

운영 설정에서 `일반 이사 예약`과 `비영리 도움 요청` 모드를 선택합니다. 일반 사용자에게 설정 화면을 노출하지 않고, 고객 공개 API에는 현재 모드만 제공합니다.

- 일반 모드: 견적, 쿠폰, 예약 용어 사용
- 비영리 모드: 도움 요청 용어 사용, 금액과 상업적 요소 숨김

## 화면 구성 원칙

- 짙은 블루 사이드바와 고정된 상단바로 현재 위치를 명확히 표시합니다.
- 목록 상단에는 오늘 처리할 수치와 필터를 두고, 결과는 테이블로 제공합니다.
- 상태는 텍스트와 배지를 함께 사용해 색상만으로 구분하지 않습니다.
- 로딩, 빈 목록, 오류, 세션 만료 상태에서 다음 행동을 안내합니다.
- 좁은 화면에서는 사이드바를 접고 표의 핵심 열만 우선 표시합니다.

React 관리자 화면을 기본으로 사용하되, 아직 전환하지 않은 일부 기능은 Spring Boot의 기존 관리자 화면에 남아 있습니다. 기능을 옮길 때는 API와 React 화면을 먼저 검증한 뒤 기존 화면을 정리합니다.
