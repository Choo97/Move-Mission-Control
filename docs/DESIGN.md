# 디자인 가이드

이 문서는 24nalpo 화면을 어떤 방향으로 만들지 정리한 기준 문서입니다. 현재 구현된 기능을 기준으로 바로 적용 가능한 UI/UX 요소만 우선 반영합니다.

## 디자인 방향

24nalpo는 이사 예약 관리 플랫폼입니다. 전체 분위기는 공공기관 지원사업 사이트처럼 신뢰감 있고 깔끔하게 유지하되, 고객이 처음 방문했을 때 바로 예약을 접수할 수 있는 실용적인 서비스로 보여야 합니다.

핵심 인상은 다음과 같습니다.

- 쉽고 빠르게 이사 예약을 접수할 수 있다.
- 예약 가능 시간과 진행 상태를 확인할 수 있다.
- 관리자 확인, 견적 확인, 사진 업로드까지 이어지는 흐름이 명확하다.
- 화면은 과하게 화려하기보다 신뢰감 있고 정돈되어 있다.

## 색상과 분위기

메인 컬러는 블루 계열을 사용합니다. 블루는 공공기관형 사이트에서 신뢰, 안정, 안내의 느낌을 주기 좋기 때문에 고객용 예약 서비스에 적합합니다.

기본 구성은 다음과 같습니다.

- 배경: 밝은 화이트 또는 연한 블루 그레이
- 주요 버튼: 진한 블루
- 보조 버튼: 연한 블루 배경
- 카드: 화이트 배경, 얇은 테두리, 부드러운 그림자
- 강조 텍스트: 블루 계열
- 오류, 취소, 실패 안내 문구도 가능한 빨간색을 피하고 검정에 가까운 중립 색을 사용합니다.

기존 coral 테마는 보조 테마 또는 실험 테마로 유지할 수 있지만, 고객용 기본 화면은 블루/화이트 테마를 우선합니다.

## 인터랙션 효과

화면의 반응은 과하지 않게 구성합니다. 공공기관형 사이트의 신뢰감을 유지해야 하므로 큰 움직임보다 사용자가 현재 조작 중인 요소를 알아보기 쉬운 정도의 효과를 사용합니다.

- 버튼에 마우스를 올리면 더 진한 블루로 바뀝니다.
- 버튼 hover 시 약한 그림자와 1px 정도 떠오르는 효과를 사용합니다.
- 서비스 특징 카드와 안내 카드에는 hover 시 하단 한 줄 높이의 네모 박스가 왼쪽에서 오른쪽으로 서서히 채워지는 효과를 사용합니다.
- 카드 hover 효과는 텍스트를 가리지 않도록 카드 하단에만 배치합니다.
- 모바일에서는 hover가 핵심 동작이 아니므로 정보 전달은 항상 기본 상태에서도 가능해야 합니다.

## 상단 구조

상단 헤더에는 다음 요소를 배치합니다.

- 로고 영역
- 서비스명 `24nalpo`
- 고객 주요 메뉴
- 관리자 진입 버튼

메뉴는 현재 구현된 화면 기준으로 구성합니다.

- 이사 예약
- 이용 안내
- 예약 조회
- 관리자

추후 별도 페이지가 생기면 아래 메뉴를 확장할 수 있습니다.

- 서비스 소개
- 고객센터
- 개인정보처리방침
- 이용약관

## 첫 화면

첫 화면은 고객이 바로 행동할 수 있는 Hero 영역으로 구성합니다.

메인 타이틀:

```text
간편하게 예약하고 편하게 이사하세요
```

서브 타이틀:

```text
출발지와 도착지, 이사 날짜만 입력하면 예약 접수가 가능합니다.
```

CTA 버튼:

- 이사 예약하기
- 예약 조회하기

시각 요소는 이삿짐 박스, 트럭, 집, 지도, 일정 관리를 연상시키는 형태를 사용합니다. 현재 프로젝트에서는 별도 이미지 자산을 만들기 전까지 CSS 기반 일러스트로 표현합니다.

## 서비스 특징 카드

서비스 특징은 카드형 UI로 보여줍니다.

| 항목 | 설명 |
| --- | --- |
| 빠른 예약 접수 | 온라인으로 간편하게 이사 예약을 신청할 수 있습니다. |
| 예약 가능 시간 확인 | 운영 시간과 휴무일을 기준으로 가능한 시간만 선택합니다. |
| 예약 상태 조회 | 예약번호와 연락처 인증으로 진행 상태를 확인합니다. |
| 사진 업로드 | 이삿짐 사진을 등록해 더 정확한 상담을 받을 수 있습니다. |

## 예약 진행 절차

예약 진행 절차는 타임라인 형태로 구성합니다.

```text
STEP 01 예약 정보 입력
STEP 02 가능 시간 선택
STEP 03 예약 접수 완료
STEP 04 관리자 확인
STEP 05 견적 확인 및 이사 진행
```

이 구조를 사용하는 이유는 고객이 예약 후 무엇을 기다려야 하는지 쉽게 이해할 수 있기 때문입니다.

## 예약 작성 화면

예약 작성 화면은 모바일 사용성을 우선합니다.

- 입력 필드는 한 줄에 너무 많이 배치하지 않습니다.
- 예약 작성은 `고객 정보 -> 이사 일정 -> 이사 주소 -> 추가 정보` 단계형으로 구성합니다.
- 날짜와 시간은 가능한 값만 선택하게 합니다.
- 필수 입력값은 명확하게 표시합니다.
- 임시 저장 기능은 고객이 작성 중 이탈해도 다시 이어갈 수 있게 돕습니다.
- 예약 완료 후에는 예약번호와 다음 행동을 분명히 보여줍니다.

단계형으로 구성하는 이유는 한 화면에 입력칸이 많아 보이면 고객이 부담을 느낄 수 있기 때문입니다. 기존 예약 API 구조는 유지하고, 화면에서만 입력 과정을 나누어 기능 변경 없이 사용성을 개선합니다.

## 예약 완료 화면

예약 완료 후에는 고객이 예약번호를 놓치지 않도록 완료 전용 카드를 보여줍니다.

- 예약 접수 완료 문구를 먼저 보여줍니다.
- 예약번호를 가장 크게 표시합니다.
- 현재 예약 상태를 예약번호와 가까운 위치에 표시합니다.
- 예약 당시 연락처를 함께 보여줘 고객이 조회에 필요한 정보를 바로 알 수 있게 합니다.
- 예약 조회에는 예약번호와 연락처가 필요하다는 안내를 제공합니다.
- 관리자 확인, 상담, 견적 안내, 견적 동의 후 확정 흐름을 짧게 안내합니다.
- 예약 조회, 조회 정보 복사, 짐 사진 업로드로 이어지는 다음 행동 버튼을 제공합니다.
- 사진 업로드는 예약 직후 고객이 할 수 있는 가장 자연스러운 후속 행동이므로 완료 카드에서 바로 이동할 수 있게 합니다.

이 화면이 중요한 이유는 고객이 예약번호를 알아야 이후 예약 조회, 수정, 사진 업로드, 견적 확인을 진행할 수 있기 때문입니다.

## 예약 조회 화면

예약 조회 화면은 단순해야 합니다.

- 예약번호 입력 영역을 먼저 보여줍니다.
- 연락처 인증이 필요한 이유를 짧게 안내합니다.
- 조회 결과는 예약 상태, 이사 날짜, 출발지, 도착지, 견적 상태를 카드 형태로 정리합니다.
- 사진 업로드, 리뷰 작성, 견적 확인 버튼은 다음 행동으로 명확히 배치합니다.
- 조회 전에는 예약번호와 연락처를 어디서 확인해야 하는지 짧은 단계 안내를 제공합니다.
- 조회 후에는 현재 상태, 이사 일정, 예상 금액을 상단 요약 카드로 먼저 보여줍니다.

## 빈 화면과 오류 화면

빈 화면과 오류 화면은 고객이나 관리자가 다음 행동을 바로 알 수 있게 구성합니다.

- 단순히 `없습니다`만 표시하지 않고, 왜 비어 있는지와 다음에 무엇을 하면 되는지 함께 안내합니다.
- 예약 조회 실패는 강한 경고 색상보다 중립적인 안내 박스로 표시해 고객이 실수로 느끼는 부담을 줄입니다.
- FAQ가 비어 있거나 불러오지 못한 경우에도 예약 신청과 예약 조회는 계속 사용할 수 있음을 알려줍니다.
- 관리자 목록이 비어 있을 때는 필터, 검색어, 거리 확인 조건을 조정하라는 안내를 제공합니다.

이렇게 배치한 이유는 빈 화면이 서비스 오류처럼 보이지 않게 하고, 고객이나 관리자가 화면에서 바로 다음 행동을 결정할 수 있게 하기 위해서입니다.

## 모바일 화면 기준

고객은 모바일에서 예약을 접수하거나 조회할 가능성이 높으므로, 모바일에서는 터치하기 쉬운 크기와 세로 흐름을 우선합니다.

- 주요 버튼은 최소 48px 높이로 유지합니다.
- 입력 필드는 모바일 확대를 줄이기 위해 16px 글자 크기를 사용합니다.
- 단계 표시기는 모바일에서 설명 문구를 줄이고 현재 단계만 빠르게 확인할 수 있게 합니다.
- 예약 상세 정보는 좌우 배치보다 세로 배치를 우선해 주소와 금액이 잘리지 않게 합니다.
- 사진 목록은 모바일에서 1열로 보여 터치 영역과 파일명을 확보합니다.

## FAQ 화면

FAQ 화면은 카드형 또는 아코디언 UI로 구성합니다.

- 질문 목록은 한눈에 스캔하기 쉽게 합니다.
- 답변은 펼쳤을 때만 보이게 합니다.
- 예약, 견적, 사진 업로드, 취소, 개인정보 관련 질문을 구분할 수 있게 확장합니다.

## 관리자 화면

관리자 화면은 고객용 화면보다 실무적으로 구성합니다. 제공된 24nalpo Admin 시안을 기준으로 짙은 블루 사이드바, 화이트 카드형 업무 영역, 촘촘한 테이블, 명확한 상태 배지를 사용합니다.

- 로그인 화면은 고객 화면과 분리해 관리자 전용 보안 진입 화면처럼 보여줍니다.
- 좌측 사이드바는 예약 관리, 알림 이력, 리뷰 관리, 운영 설정, FAQ 관리, 운영 가이드로 고정합니다.
- 상단바는 현재 메뉴명, 통합 검색, 빠른 이동, 알림, FAQ, 관리자 정보, 로그아웃을 제공합니다.
- 예약 목록은 처리 우선순위 요약, 필터, 테이블, 알림 처리 대상을 한 화면에서 확인하게 합니다.
- 예약 상세는 목록 옆 작은 패널이 아니라 최근 예약 목록과 상세 업무 영역을 나눈 구조로 보여줍니다.
- 알림, 리뷰, FAQ, 운영 설정, 운영 가이드는 같은 카드/테이블/상태 배지 스타일을 공유합니다.
- 로딩, 빈 목록, 오류, 권한 만료 상태도 같은 관리자 디자인 시스템 안에서 보여줍니다.

이렇게 정리한 이유는 관리자 기능이 많아질수록 화면마다 디자인이 달라지면 운영자가 정보를 찾기 어렵기 때문입니다. 공통 사이드바와 상단바를 유지하면 현재 위치와 다음 작업을 빠르게 판단할 수 있습니다.

## 푸터

푸터에는 서비스 신뢰도를 높이기 위한 기본 운영 정보만 간결하게 배치합니다. 메인 화면이 이미 카드와 섹션을 많이 사용하므로 푸터는 디자인을 최소화하고, 얇은 구분선과 작은 텍스트 중심으로 구성합니다.

- 회사명
- 사업자 정보
- 연락처
- 이메일
- 개인정보처리방침
- 이용약관

현재는 실제 사업자 정보가 정해지지 않았으므로, 화면에는 임시 안내 문구를 표시합니다. 실제 운영 정보가 확정되면 placeholder 문구를 실제 회사명, 사업자등록번호, 연락처, 이메일, 약관 링크로 교체합니다.

푸터는 메인 예약 화면, 예약 조회 화면, FAQ 화면처럼 고객이 보는 화면에 배치합니다. 관리자 화면은 실무용 화면이므로 고객용 푸터를 노출하지 않습니다. 푸터에는 별도 카드형 박스를 사용하지 않고, 서비스명, 짧은 설명, 주요 링크, 임시 운영 정보 안내만 표시합니다.

## 적용 우선순위

현재 프로젝트에 우선 적용할 수 있는 범위는 다음과 같습니다.

1. 고객 메인 화면 Hero 개선
2. 고객 예약 화면 UI 정리
3. 예약 조회 화면 UI 정리
4. FAQ 화면 카드형 구성
5. 예약 가능 시간 선택 UI 개선
6. 푸터 정보 정리
7. 버튼과 카드 hover 효과 정리
8. React 관리자 화면 디자인 시스템 적용

관리자 화면은 React 화면을 기준으로 예약 목록, 예약 상세, 알림 이력, 리뷰 관리, 운영 설정, FAQ 관리, 운영 가이드까지 같은 디자인 시스템을 적용합니다. 기존 Thymeleaf 화면은 필요할 때 비교하거나 되돌릴 수 있는 백업 성격으로 유지합니다.

아직 실제로 구현하지 않은 기능은 디자인에서 과하게 강조하지 않습니다. 문자 알림, 실시간 통계, 외부 지도 기반 거리 계산 등은 추후 기능으로 분리하고, 현재 화면에서는 안내 수준으로만 표현합니다.
