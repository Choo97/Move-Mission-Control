# 디자인 가이드

24nalpo의 고객·관리자 화면이 같은 기준으로 보이도록 정리한 UI/UX 원칙입니다. 현재 구현된 화면을 기준으로 유지합니다.

## 디자인 방향

- 공공 서비스처럼 신뢰감 있고 정돈된 인상
- 예약과 조회 행동이 먼저 보이는 실용적인 구성
- 블루와 화이트 중심의 밝은 화면
- 고객 화면은 쉬운 흐름, 관리자 화면은 빠른 판단을 우선
- 과한 장식보다 충분한 여백과 명확한 정보 위계 사용

## 시각 기준

| 요소 | 기준 |
| --- | --- |
| 배경 | 화이트 또는 연한 블루 그레이 |
| 주요 색상 | 진한 블루 |
| 보조 색상 | 밝은 블루, 청록, 주황 |
| 카드 | 흰 배경, 얇은 테두리, 약한 그림자, 8px 이하 모서리 |
| 본문 | 검정에 가까운 중립 색상 |
| 오류·실패 | 아이콘과 문구로 구분하고 빨간 글씨는 최소화 |
| 글꼴 | Pretendard 우선, 시스템 sans-serif 대체 |

색상만으로 상태를 전달하지 않습니다. 상태명, 아이콘, 배지를 함께 사용합니다.

## 고객 화면 구조

상단 메뉴는 현재 제공하는 기능만 노출합니다.

- 이사 예약 또는 도움 요청
- 이용 안내
- 예약 조회
- FAQ
- 관리자 로그인

### 메인 화면

- 첫 화면에서 서비스명, 핵심 문장, 예약·조회 버튼을 바로 보여줍니다.
- 이삿짐, 집, 일정, 경로를 연상시키는 실제 이미지나 구현된 시각 요소를 사용합니다.
- 서비스 특징, 진행 절차, 공개 후기, FAQ 순서로 고객의 의사결정을 돕습니다.
- 다음 섹션 일부가 첫 화면 아래에 보여 페이지가 이어진다는 점을 알립니다.

### 예약 작성

예약 폼은 `고객 정보 -> 이사 일정 -> 주소 -> 추가 정보 -> 최종 확인` 단계로 나눕니다.

- 한 화면에 입력 필드를 과하게 배치하지 않습니다.
- 운영시간과 휴무일을 반영해 선택 가능한 날짜와 시간만 표시합니다.
- 선택한 날짜에 시간이 없으면 예약 가능으로 표시하지 않습니다.
- 임시 저장과 이전 단계 이동을 제공해 입력 중 이탈 부담을 줄입니다.
- 완료 화면에서는 예약번호, 연락처, 현재 상태와 다음 행동을 먼저 보여줍니다.

### 예약 조회와 상세

- 조회 화면은 예약번호와 연락처 입력에 집중합니다.
- 인증이 필요한 이유와 번호를 확인할 위치를 짧게 안내합니다.
- 상세 화면은 상단 요약, 진행 단계, 일정·주소, 견적, 사진, 고객 요청, 후기로 구분합니다.
- 내용이 많은 상세 화면은 넓은 영역과 내부 탐색 링크를 사용해 긴 세로 흐름을 줄입니다.

### 비영리 도움 요청

비영리 랜딩은 일반 예약 화면과 분리된 첫 화면을 사용합니다. 이후 입력·조회 컴포넌트는 재사용하되 용어와 노출 정보는 서비스 모드에 맞춥니다.

- `예약` 대신 `도움 요청`, `고객` 대신 `신청자` 사용
- 견적, 쿠폰, 결제 등 상업적 요소 숨김
- 지원 가능 여부와 일정 조율 과정을 명확히 안내

### FAQ와 푸터

FAQ는 질문을 빠르게 찾을 수 있는 아코디언으로 구성합니다. 푸터는 별도 카드 없이 얇은 구분선, 서비스명, 연락처, 정책 링크만 간결하게 표시합니다.

## 관리자 화면

관리자 화면은 짙은 블루 사이드바, 화이트 업무 영역, 촘촘한 표와 상태 배지를 공통으로 사용합니다.

- 로그인: 고객 화면과 분리된 보안 진입 화면
- 상단바: 현재 메뉴, 통합 검색, 빠른 이동, 알림, 관리자 정보, 로그아웃
- 예약 목록: 처리 우선순위, 검색·필터, 테이블, 페이지 이동
- 예약 상세: 고객 흐름 요약, 예약 정보, 현장 정보, 운영 처리, 요청·알림 이력
- 알림·리뷰·FAQ: 요약 수치, 필터, 목록, 예약 상세 이동
- 운영 설정: 서비스 모드, 운영시간, 휴무일, 견적 정책을 영역별로 저장

관리자 화면의 정보 배치 이유와 운영 규칙은 [관리자 기능 가이드](ADMIN.md)에 정리합니다.

## 상호작용

- 버튼 hover 시 배경을 한 단계 진하게 하고 약한 그림자를 표시합니다.
- 정보 카드 hover 시 카드 하단에 한 줄 높이의 색상 영역이 왼쪽에서 오른쪽으로 채워집니다.
- hover 효과가 텍스트를 가리거나 필수 정보를 대신하지 않게 합니다.
- 저장, 승인, 반려처럼 결과가 남는 작업은 처리 중·성공·실패 상태를 화면에 표시합니다.
- 익숙한 기능은 아이콘을 사용하고, 의미가 모호한 아이콘에는 툴팁이나 접근성 이름을 제공합니다.

## 반응형 기준

- 모바일 주요 버튼과 입력 필드는 최소 48px 높이를 사용합니다.
- 입력 글자 크기는 16px 이상으로 유지해 모바일 자동 확대를 줄입니다.
- 고객 화면은 세로 흐름을 우선하고, 주소와 금액이 잘리지 않게 합니다.
- 관리자 표는 핵심 열을 우선 표시하고 나머지는 가로 스크롤이나 상세 화면에서 제공합니다.
- 버튼, 배지, 긴 파일명과 주소가 서로 겹치지 않는지 모바일과 데스크톱에서 확인합니다.

## 화면 상태와 문구

- 로딩: 현재 불러오는 대상을 알려주고 레이아웃이 크게 움직이지 않게 합니다.
- 빈 화면: 비어 있는 이유와 필터 초기화 등 다음 행동을 함께 제공합니다.
- 오류: 콘솔에만 의존하지 않고 화면에서 재시도 방법을 안내합니다.
- 세션 만료: 관리자에게 재로그인 버튼을 제공합니다.
- 고객 문구에는 `공개 처리`, `관리 대상` 같은 내부 운영 표현을 사용하지 않습니다.
- 아직 구현하지 않은 결제, 지도 거리 계산, 카카오 알림톡은 현재 기능처럼 표현하지 않습니다.
